# day11-testing-async

## Why Testing Matters
- Finds bugs early
- Improves reliability
- Prevents failures
- Ensures correct functionality

---

## What is Asynchronous Processing
Asynchronous processing runs tasks in the background without making users wait.

Examples:
- Batch jobs
- Email sending
- API callouts
- Scheduled tasks

---

## Important Test Cases
- Valid input testing
- Invalid input testing
- Bulk data testing
- Async execution testing
- Error handling

---

## Async Use Cases
- Large data processing
- Background calculations
- External integrations
- Scheduled operations

---

## Reliability Discussion
Reliable systems:
- Handle failures properly
- Support many users
- Maintain stable performance
- Recover from errors

# Revision Questions

1. Why is testing important?  
Testing improves software quality and reliability.

2. What problems happen without testing?  
Bugs, crashes, and incorrect results.

3. Difference between synchronous and asynchronous execution?  
Synchronous waits; asynchronous runs in background.

4. Why do enterprise systems use background jobs?  
To avoid blocking users during heavy processing.

5. Why should developers think about scalability?  
Systems must support growing users and data.

6. Why are test cases important?  
They verify application behavior.

7. What happens when systems fail partially?  
Some services stop while others continue.

8. Why do large systems require reliability engineering?  
Failures impact many users and businesses.

9. Why should enterprise software avoid blocking operations?  
Blocking reduces performance and productivity.

10. Why is enterprise software different from small scripts?  
It handles large-scale users, data, and reliability requirements.
